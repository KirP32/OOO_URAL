# Деталь — поиск автозапчастей

Клиентское приложение на React, Redux Toolkit и JavaScript. Стили — Bootstrap 5 и обычный CSS. Сборка — Vite. Backend не нужен: запросы уходят напрямую в HTTPS API Favorit Parts.

## Запуск

Нужен Node.js 22.12+; рекомендуемая версия указана в `.nvmrc`.

```bash
git clone git@github.com:KirP32/OOO_URAL.git
cd OOO_URAL
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite, введите собственный ключ покупателя Favorit Parts и нажмите «Использовать ключ». Затем введите артикул, дождитесь производителей и выберите бренд.

API-ключ хранится только в памяти вкладки. Приложение не записывает его в localStorage, sessionStorage, cookies, файлы или сборку. Redux DevTools отключены. Перезагрузка страницы удаляет ключ. Ключ отправляется непосредственно в Favorit Parts в GET-параметре `key`, как требует API. Поэтому для размещения приложения используйте доверенный HTTPS-хостинг.

## Реализованное поведение

- Поиск производителей автоматически через 450 мс после последнего изменения артикула; кнопка «Найти» запускает его сразу.
- Выбор бренда запрашивает исходную деталь и аналоги.
- Отдельная строка таблицы для каждого склада: наименование, производитель, артикул, склад, цена и остаток.
- Цена берётся только из `warehouses[].price`, остаток — из `warehouses[].stock`. Устаревшее поле товара `price` не используется.
- Товары без складов остаются в списке с отметкой «Нет цены» и суммарным остатком `count`; нулевой остаток отображается как «Нет в наличии». Отсутствующее значение не подменяется нулём.
- Отдельные индикаторы загрузки, пустые результаты, понятные ошибки ключа, квоты, HTTP, сети, некорректного и пустого ответа; повтор запросов.
- Таймаут 20 секунд; отмена запросов и защита от устаревших ответов при изменении артикула, производителя или ключа.
- Адаптивный интерфейс, доступные подписи полей, клавиатурное управление; на узком экране таблица прокручивается горизонтально.

## API

[Документация Favorit Parts](https://lk.favorit-parts.ru/static/wsprice.pdf), версия от 06.03.2023.

Первый запрос:

```text
GET https://api.favorit-parts.ru/hs/hsprice/?key=<ключ>&number=<артикул>
```

Второй запрос:

```text
GET https://api.favorit-parts.ru/hs/hsprice/?key=<ключ>&number=<артикул>&brand=<бренд>&analogues=on
```

Специальные символы кодируются через `URLSearchParams`. Ответ — объект с массивом `goods`; аналоги находятся в `goods[].analogues`. Документированный ответ с пустым товаром обрабатывается как отсутствие результатов. Ошибки могут приходить в поле `error`, в том числе с неуспешным HTTP-статусом.

В PDF указан HTTP-адрес; приложение использует HTTPS. 19.10.2026 запрос без ключа подтвердил доступность HTTPS: `403`, `{"error":"Empty key!"}`, заголовок `Access-Control-Allow-Origin: *`. В браузере также проверен ответ на заведомо неверный тестовый ключ: `Invalid access key`; этот вариант добавлен к ошибкам из PDF. Успешные ответы с личным ключом при разработке не проверялись. Если сервис изменит CORS-политику, потребуется прокси на стороне хостинга: режим `no-cors` не позволяет прочитать JSON и не решает эту проблему.

## Структура

```text
src/
  api/parts.js              HTTP, ошибки, преобразование данных
  store/search.js           Redux-состояние и асинхронные запросы
  components/ApiKeyForm.jsx  Ввод и удаление личного ключа
  components/BrandList.jsx   Выбор производителя
  components/OffersTable.jsx Предложения по складам
  components/RequestState.jsx Загрузка, ошибки и пустые результаты
  App.jsx                   Экран поиска и отмена запросов
  styles.css                Адаптивное оформление
```

## Проверки и сборка

```bash
npm test
npm run build
npm run preview
```

Тесты используют Vitest и React Testing Library. Подменяется только `fetch`, Redux и компоненты работают совместно. Фикстуры доступны только в тестах; интерфейс показывает данные реального API. Для размещения на статическом хостинге используйте содержимое `dist/` после сборки. Внешний шрифт Google Fonts необязателен: без сети используется системный sans-serif.
